# 验收记录 · 0.4.9 alpha

本记录区分现场行为、程序状态核验与模拟结果，不将接口存在或模拟成功当作硬件兼容性证明。

## 0.4.9：临时靠拢候选，真机待验收

用户授权中间屏断开后临时靠拢，保留主屏、旋转与相对顺序；重连恢复完整原排列。已实现通用保守规划、请求绑定和独立完整快照，拒绝任意漂移、快照覆盖与并发改变后的布局重放。复杂且无法安全规划的拓扑提前拒绝，详见[策略](TEMPORARY_LAYOUT.md)。

本地及公开副本各130项Swift单测（127核心、3UI）和28项进程模拟（8恢复、8单屏、5输入、2审计、5临时排列）通过；Release构建与App/helper严格签名通过。旧单屏回归检测到提示文字兼容问题，修正后重跑通过。模拟原生界面观察到执行进度及45秒面板，画面正常、位于可见区域；模拟点击恢复后四屏恢复。没有执行真实断屏、旋转或切源。

本机安装0.4.9 build16前后只读核对四屏与开机标识相同，未产生新真实事务。**Redmi的新断开策略、完整重连恢复以及真实重排中的面板可见性仍未验收。** 下面的真实成功/失败均为旧版本历史，不标成新版通过。

## 现场：2026-10-14

一台 Apple Silicon Mac Studio，macOS 27.0.1，四块实体屏，目标 U2777B。全部真实操作由用户在 App 中主动确认执行，agent 没有代点。

- 断开后布局核验成功，进入 45 秒确认；用户点击“保留断开”，事务记录为 confirmed。
- 保持约 3 分 12 秒后，用户手动发起连接，软件核对目标已活动且布局恢复；用户确认本次成功。
- 连接后只读状态与断开前快照一致，包括四屏布局/旋转；开机标识一致。
- 这只证明此配置的一次成功。较早版本曾出现提前回连、黑屏与恢复失败；本次成功不消除私有 API 和硬件恢复风险。

原始现场快照、屏幕身份和审计日志留在本机，未公开。仓库回归夹具替换了 UUID、数字显示器 ID、厂商/型号/序列、名称、时间、开机标识和事务身份，去掉真实许可并设置为 simulation。保留的布局几何用于重排回归；模拟耗时序列是构造值，不是对缺失现场样本的还原。

## Redmi 27 NU：0.4.8最终布局核验仍失败

随后用户在同一环境用 0.4.7 测试 Redmi 27 NU，断开后约 1.74 秒进入保护恢复，约 2.82 秒核验回连。事务从 applying 直接转 restoring，没有进入 awaitingConfirmation，所以不是 45 秒超时或未及时点“保留断开”。agent 只读取已有记录，没有重复真实操作。

分阶段审计显示：

- 禁用及配置提交均返回成功，目标离开活动清单。其余三屏身份保持一致，保留实体屏一直活动，无镜像/指纹拒绝。
- macOS 将三屏重排为横向布局，并改变主屏角色，将另一块原 270° 竖屏报告为 0°。这些差异需要通用布局协调，不能直接确认成功。
- 初始稳定窗口内取得 **6 次完全一致且及时完成** 的观察，第 6 次约在窗口开始后 1.096 秒完成。
- 宽限期尚未结束，循环又发起第 7 次读取；它约在 1.235 秒完成，超过 1.2 秒期限约 35 毫秒。`DisconnectStabilizer.wait` 的读后截止分支清空了此前累计的观察，最终错误地报告“未取得两次一致观察”。
- 没有进入布局协调，也没有调用旋转协调。保护随后启用目标；当前只读四屏布局/旋转与本次原快照一致。

使用已有读取完成时间和合成身份，对**未修改的生产稳定采样函数**做隔离离线回放，复现了六次有效观察被最后一次晚读清空的错误分支。回放测试断言的是现有失败，不是修复通过。之前的测试没有覆盖“已有足够一致的重排样本、最后一次读取跨截止”这一组合。

结论：本次直接原因是通用采样期限与重排宽限期的衔接缺陷；目前没有证据要求逐型号适配。不同硬件仍可能触发不同系统重排或延时，本次诊断不能保证后续旋转/布局协调一定成功。应先离线修正并补足这一通用状态转换的安全回归，保留身份、取消、期限及写入前新鲜状态核对；不能简单跳过保护或接受过期读数。

此前说明提交只修正文档。现在0.4.8已修改通用采样状态转换，停止在足够新鲜的重排证据上启动多余末次读取，并在宽限等待中监视失效。晚读、陈旧、冲突、取消和身份异常仍拒绝。详见[状态机与回归](STABILITY.md)。当前仍只有U2777B的一次持久断开与手动回连通过；Redmi的0.4.8持续断开、后续旋转/布局协调均待用户现场验收，未上传原始事务、真实身份或日志。

### 0.4.8后续两次现场结果

两次真实事务均由用户自行发起。0.4.8的初始稳定样本形成有效证据并完成宽限，进入布局协调；两次都在最终核验阶段失败。一次约5.58秒、最新一次约4.01秒完成保护回连，均没有进入 `awaitingConfirmation`，没有确认/取消标记。

最终每次各8次读数均显示同一差异：保留屏U2777B的x为1920，原快照要求3000；其他原布局字段匹配。配置位置及提交调用返回成功，不能据此推断原位置实际保持。被停用的Redmi原来占据两屏之间1080点宽的区域，差值与此相同；系统是否禁止留下这种布局空隙仍未核实，不将推测作为事实或放宽核验。

用户报告操作窗口消失且未看到倒计时。源码在发起操作后主动关闭单屏操作sheet；其生命周期与AppDelegate持有的独立确认NSPanel分开。确认面板仅在helper进入确认阶段后显示，本次两次均未到达该路径。没有面板show/visible/frame/screen/key/Space或点击记录，因此不能用当前窗口的isVisible或事后截图证明当时用户可见；也没有证据表明sheet关闭连带销毁了确认面板。管理窗口当时是否移到不可见区域或被遮挡，现有历史日志不能重建。

当前四屏及开机标识与两次原快照均一致。此次只读诊断，没有修改底层或UI、没有重新安装或执行额外断屏测试。初始截止修复已有现场阶段证据，但Redmi持续断开仍未通过；后续需要解决原布局要求与实际系统排列结果的差异，不能把故障归为单纯倒计时UI问题。

| helper ready → applying | 0.313 秒 |

## 0.4.8历史公开副本验证

公开副本与同版本本地候选的功能代码差异仅为包标识匿名化，以及移除针对一块真实设备的接线标签提示。未改变实际显示写入或恢复策略。公开副本未另行执行真实屏幕测试。

- Release 构建通过，App 与 helper 的 ad-hoc 严格签名验证通过。
- Swift 单元测试：116 项（核心 113，确认面板定位 3），零失败。
- 进程模拟：23 项（恢复 8、单屏 8、输入源 5、追加审计 2），全部通过；无真实显示写入。
- 覆盖请求许可绑定/过期、UUID/指纹歧义、保留屏/镜像、取消/重复进程、helper 脱离 UI 后恢复、新屏保留、旋转/布局核验、有限稳定采样与读后截止、审计追加及审计存储故障。
- 进程测试的请求 nonce 与目录匹配，符合生产审计会话约束。全部数据为模拟数据。
- macOS 26+ 的正式 `glassEffect` 与 macOS 27 菜单接口在当前 SDK 构建通过；不代表旧系统或不同硬件的实机验收。
