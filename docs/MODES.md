# 工作模式与输入源 · 0.5.2 alpha

菜单栏和管理窗口都有“办公室”“远程单屏”，远程保留屏默认当前主屏，也可从管理基线明确选择。按钮先显示受影响屏幕/操作清单及现场确认；不自动判断远控会话，不搬其他App窗口。模式依据实际活动集合、身份和布局显示为办公室、远程或部分状态。

## 两份快照与单一事务

- `mode-office.json`保存完整办公室基线；首次模式进入前持久化，之后不会被逐屏断开的中间布局覆盖。只有屏幕连齐时，“以当前排列为准”才能重新保存。
- 每次事务的`request.before`保存实际入口，`request.office`引用完整基线。办公室恢复完整基线；远程A切到B取消时，恢复A，而非四屏。办公室恢复失败、取消或未确认时保留已连接屏幕，不重新禁用来回到单屏入口；缺失屏幕只尝试启用，未知布局不覆盖。
- 保留屏离线时先启用、读取核验，再调整主屏，最后逐个停用其他非主屏。每步前新鲜状态核对，至少一块实体屏保留。UUID优先，恢复回退限同次开机及唯一硬件指纹；模式不支持镜像或关闭内置屏。
- 一个独立owner持有进程锁，串行运行最长10秒的子步骤，切换执行预算90秒；所有步骤完成并核验后，才启动唯一45秒确认。没有嵌套的单屏确认计时器。模式保持单次请求许可，旧无约束批量路径仍关闭。
- 远程超时/取消按已知检查点恢复本次入口；办公室恢复只连接屏幕，失败可报告部分状态；未知人工移动、新屏或不完整枚举时，仅尝试启用入口屏幕，停止覆盖布局并报告部分恢复。不会关闭未知新屏。回滚不能保证硬件或WindowServer故障时成功。
- 关闭管理窗或正常退出会请求取消；强退UI后owner仍拥有计时器。owner也观察睡眠/唤醒并取消过期流程。owner异常退出时保留入口、基线和检查点，下次启动提示恢复未确认；不会盲目自动重放旧禁用计划。跨开机缓存不能用于真实恢复，需要连齐屏幕重新识别。

本版本复用CoreGraphicsBackend、UUID恢复、原模式/旋转封装和几何核验，新增模式编排及主屏过渡。**0.5.1远程单屏用户已确认保持，但办公室恢复失败；0.5.2修复及跨保留屏切换尚未真机验收**；此前单屏成功不能等同这些新路径通过。复杂且无法安全生成逐屏过渡的排列会预先拒绝。临时启用多个屏幕时可先排成紧凑横向过渡，最终办公室严格核对原布局。

## 每屏信号源

点击任意屏幕（菜单栏也可进入）即可打开输入源控制。Mac是否启用、最后一次DDC读回、上次切换请求分别显示。读回或写入返回成功都不证明实体画面已显示目标主机。

先只读检测当前输入，再由用户在实体OSD核对并记录端口名称。两个真实端口必须分别实读校准；UI只使用已记录名称，不凭常见HDMI/DP代码猜测。只剩一块Mac画面、目标为主屏/内置屏、镜像、读数过期或路由不明时禁止切走。端口代码/路由留在诊断详情，不作为日常选择尾号。

输入源独立于模式事务。切换前有二次确认和现场OSD回退说明，切走后可能失去DDC通道；不能保证从Mac切回。实际Set和切回仍未验收。首次应在全部屏幕正常的办公室状态下，以非主屏为目标，另一块Mac实体屏保持可操作；不得与模式切换同时测试。

## 建议首次现场步骤（未执行）

1. 确认完整办公室排列正确，保留当前主屏，能单独重新插拔受影响屏幕视频线；远控可能短断。
2. 用户点击远程单屏，核对保留屏和逐屏影响清单后主动确认。
3. **第一次不点保留**，等待唯一45秒计时结束；应尝试回到本次入口四屏、原主屏、原旋转和排列。
4. 异常时点立即恢复；若软件失败，用目标屏OSD选回Mac输入，必要时单独重插该屏视频线，不拔保留屏或整只扩展坞。停止重复测试并保留记录。
5. 该回退通过后，再另行测试“保留远程→办公室”和不同保留屏之间切换。DDC切源需另外完成端口校准再单独测试。

0.5.2只对观察器明确报告“仍在重配”的失败重试只读采样，保留原2.5秒步骤稳定窗口与外层8/10秒限制；不重发硬件写入，不接受过期或身份不符数据。办公室恢复的步骤失败会保留已连接屏幕并显示缺失屏幕/排列未核验详情。用户取消时停止后续补连，不退回单屏。
