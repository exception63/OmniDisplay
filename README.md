# OmniDisplay

原生 macOS 菜单栏显示器管理工具，使用 SwiftUI / AppKit。中文管理窗口动态展示屏幕清单、主屏、连接状态与布局，支持逐块连接、断开外接显示器；macOS 26+ 使用正式 Liquid Glass API，旧系统退化为原生材质。

**实验性 alpha · 0.5.3 build20已安装并正式运行（2026-10-15）。** 在同一台 Apple Silicon Mac Studio/macOS 27.0.1四屏环境中，U2777B、Redmi 27 NU、U27N3R已有用户单屏断开—保留—重连成功记录。0.5.1远程单屏保持成功，但办公室恢复失败并再次禁用了屏幕；0.5.2修复仍待现场复测。其他机器/系统和长期稳定性未验证，独立恢复进程不能保证WindowServer或硬件故障时恢复，首次测试必须在现场进行。

**Redmi 27 NU 在0.4.8的两次实测仍未通过。** 初始稳定阶段已通过，但最终布局核验发现另一块保留屏U2777B的横坐标仍比原快照少1080点，保护回连。两次均未进入45秒确认，倒计时面板没有显示；这不是“未及时点保留”。当前仅确认U2777B此前一次持久断开与手动回连，不能宣称所有显示器稳定可用。0.4.9的新临时靠拢和完整重连已由用户在同一机器上分别完成Redmi 27 NU、U27N3R各一次测试，均成功；详细边界见验收记录。[状态机与回放](docs/STABILITY.md) · [最新现场验收](docs/VALIDATION.md)。

## 功能与边界

- 单屏连接/断开；预览保留主屏、旋转和顺序的临时靠拢排列，重连恢复独立保存的完整原排列。不会搬动其他 App 的窗口。[布局规则与限制](docs/TEMPORARY_LAYOUT.md)。
- 保护主屏、内置屏和最后一块保留实体屏；身份不明、镜像、指纹歧义或不安全的拓扑变化时拒绝操作。
- 每次真实断开都要在 App 中核对目标和恢复条件，再点带目标名称的二次确认按钮。没有永久解锁。
- 独立 helper 先持锁并完成握手，执行后核对布局，随后开启 45 秒确认；超时、取消或核验失败会尝试恢复。恢复不会关闭新接入的屏幕。
- 以 UUID 识别屏幕；仅恢复启用时，允许在同一次开机、原快照及当前指纹都唯一匹配且当前 UUID 为空时回退。禁用和切源不使用该回退。
- DDC/CI 输入源读取、端口记录和固定 VCP `0x60` 单次切换流程已实现，但**真实输入源写入及切回尚未验收**。DDC 可读不代表可切换或可切回；路由不明、端口未现场校准时拒绝。

0.5.0新增有受影响清单、单次确认与独立回滚的办公室/远程模式；旧批量路径仍关闭。不自动检测悠悠会话，不创建虚拟屏，不安装驱动或常驻系统服务。[模式、输入源与首次测试](docs/MODES.md)。多屏模式、跨保留屏切换及真实DDC写入仍未真机验收。

## 构建与启动

需要 Xcode 27 SDK、Swift 工具链及 Python 3（仅运行进程测试时需要）。本次构建环境为 Swift 6.4 / macOS 27.0.1。部署目标为 macOS 14；14/15 的材质降级与 Intel 实机尚未验证，DDC 路由实现仅面向可明确识别的 Apple Silicon 硬件。无第三方 Swift 包依赖。

```sh
./scripts/build.sh
open dist.noindex/OmniDisplay.app
```

产物为 `dist.noindex/OmniDisplay.app`，内含 `OmniRecovery` helper。仅启动或打开管理窗口不会更改显示设置。关闭窗口后菜单栏应用继续运行，可用 ⌘0 打开管理窗口。可在无待处理事务时退出应用，将整个 `.app` 拷贝至 `/Applications` 后再启动；不要同时运行两份。

构建脚本进行本地 ad-hoc 签名；项目未提供开发者签名、公证或安装包，不应通过关闭系统安全保护来安装。应用不要求辅助功能或屏幕录制权限。底层显示启停、旋转和 DDC 含私有接口，API 存在只说明符号可加载，不保证某台机器可安全恢复；不保证未来 macOS 兼容。

## 第一次现场测试

1. 保持另一块实体屏有画面，先确认能通过目标屏实体 OSD 选回 Mac 输入，并能单独重新插拔目标视频线。远程连接可能短暂中断，不要首次在无人现场时测试。
2. 在管理窗选择一块非主屏外接显示器，打开“单次断开测试…”，核对目标、保留屏及两项现场确认，再由自己点击最终确认。
3. 执行/恢复阶段保留进度面板；等待临时布局核验结束。45 秒确认面板显示在仍活动的原主屏，管理窗顶栏和菜单栏也显示倒计时。画面、旋转正常且排列符合临时预览后点 **“保留断开”**；不点击会在到期后尝试恢复。异常时点“立即恢复”。
4. 需要连接时选择该屏，点“连接这块屏幕”，核对并确认。屏幕布局恢复与其他 App 窗口回位是两件事，本应用不搬窗口。

如果恢复失败，停止重复测试；用目标屏 OSD 选择 Mac 输入，必要时仅重新插拔目标视频线。不要拔保留主屏或整个扩展坞。

输入源测试是独立功能：先只读检测，并分别通过实体 OSD 确认、记录两个端口的实际代码与名称；软件不会凭 HDMI/DP 常见编码猜测接线。切走后 DDC 可能不可达，即使有超时恢复也必须能在现场手动选回。

## 验证与模拟

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/clang-cache" swift test --disable-sandbox --cache-path .build/cache --scratch-path .build
python3 scripts/test-recovery.py
python3 scripts/test-single-screen.py
python3 scripts/test-input.py
python3 scripts/test-audit.py
python3 scripts/test-temporary-layout.py
python3 scripts/test-modes.py
```

先构建再运行 Python 测试；所有进程测试强制 `simulation=true`，不执行真实显示写入。SwiftPM 的 `--disable-sandbox` 只用于构建子进程，不更改系统安全设置。

退出其他 OmniDisplay 实例后，可查看模拟界面：

```sh
./scripts/build.sh --simulation
open "dist.noindex/OmniDisplay Simulation.app" --args --demo 4 --data-dir "$PWD/artifacts/demo"
```

模拟版使用独立名称、bundle ID、偏好、进程锁和 `Simulation` 数据子目录；即使不带参数打开也只会模拟。正式版拒绝 `--demo`，从搜索启动会沿用上次正式数据目录。`--demo` 可选择不同屏幕数量。测试夹具使用合成身份，保留多屏几何关系用于回归；模拟通过不是硬件兼容性证明。验证结果和已知限制见 [验收记录](docs/VALIDATION.md)。

本次连接从开始执行到 macOS 状态核验完成约 **0.55 秒**，但用户感知实际亮屏约 10 秒。日志没有实体画面出现的时间戳，尚不能定位这段差异；没有据此缩短恢复保护或宣称延迟已修复。

## 0.5.3 build20 · 候选验证记录（2026-10-14）

源码新增最终排列提交后的只读收尾核验。原2.5秒迟到拒绝规则、worker8秒/owner10秒预算保留；仅最后arrange已成功提交但稳定核验超时才可进入新阶段。保持同一操作锁，最多2.5秒重新取得两次独立、新鲜、一致且完整匹配的读数，读取运输预算不超过剩余时间；不复用迟到样本、不重发写入、不关闭屏幕。身份、开机标识、人工布局、缺屏或读取错误不清成成功。成功回执明确“原步骤核验超时，随后只读核验恢复”，失败说明未完成核验。历史事务原文单独保留，与当前读取状态分开展示。

现场依据：0.5.2一次远程模式主动取消后，最终排列提交成功，两个有效读数在约2.272/2.516秒返回，均符合原四屏；第二次超过2.5秒截止被拒绝。用户之后看到恢复正常，事后只读也符合原布局，但历史failed不能改成当时通过。这不是独立办公室切换或45秒超时验收。

本地和公开副本各168项Swift单测（165核心+3UI布局）及54项纯simulation进程检查通过（26模式、8恢复、8单屏、5临时布局、5输入、2审计）。新增12项单测含实际匿名时间线、迟到拒绝、新收尾双读/预算/故障清除/身份/布局/boot/传输与历史展示条件；10项模式进程检查覆盖两种恢复路径的成功、超时、身份、布局、boot异常，核对没有追加工作项或禁用。Release构建和App/helper严格签名通过。模拟路径不注册真实桌面电源通知，没有启动模拟GUI。
